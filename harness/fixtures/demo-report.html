03 / Findings - 4

Fix the prefix before changing lifetime.

Findings are ranked by severity and monthly impact. Each one names the mechanism, the evidence class, and the safest next action.

TTL-1modeledquality risk: low

'research-agent' request cadence sits inside the one-hour window

~$214avoidable / month
Evidence

100% of gaps between requests fall between five minutes and one hour (median 11.2 min across 126 requests). In that band a five-minute cache expires before the next request and rewrites at 1.25x, while a one-hour cache would have read at 0.1x.

Action
Set a one-hour TTL on the static prefix for this agent. Outside the five-minute-to-one-hour band the five-minute default is cheaper, so this is not a blanket change.
EFF-1measuredquality risk: low

Cache writes are largely not being read

~$14.60avoidable / month
Evidence

Prefix efficiency is 17%: of every 100 tokens written to cache, 17 are later read. A write bills above the standard input rate, so the unread remainder is a pure premium paid for nothing.

Action
Find what invalidates the prefix between requests before changing any TTL. A longer lifetime on an unstable prefix buys nothing.
CAC-1measuredquality risk: low

Caching costs more here than sending the prompts uncached

Evidence

Cache reads and writes are 99% of input spend across 286 priced requests. That share on its own says nothing about whether caching is working -- reads bill at a tenth of the input rate, so they dominate a bill only when the volume behind them is large. The counterfactual is what settles it: the same traffic sent uncached would cost 1.0x what it does now, so caching is adding 5% to input spend. Of the cache spend itself, 2% is reads. A session that extends its prefix rather than rebuilding it tends to run near 75%, so a lower share is worth looking into -- but it is a hint and not a finding, because a workload whose turns add a lot relative to the prefix (large tool results) moves toward even without rebuilding anything. REB-1 counts rebuilds directly and is what settles it.

Action
Stop writing caches that nothing reads before tuning anything else.
MIN-1measuredquality risk: low

Cache markers on prefixes below the model minimum

Evidence

40 requests carry a cache marker on a prefix shorter than the 4,096-token minimum for claude-haiku-4-5, and returned zero cached tokens in both directions. The provider processes these uncached and reports no error, so nothing surfaces this in normal monitoring.

Action
Either lengthen the cached prefix past 4,096 tokens or drop the marker. Minimums are not monotonic across model generations, so this must be looked up per model rather than reasoned about.
